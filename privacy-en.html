Privacy Policy

October 24, 2026

This policy covers SVEED’s institutional evaluation version and sveed.com.br. The application enables curriculum-based review at home. The sections below distinguish information used on the device from information processed when visiting the website.

1. Responsible developer and contact

SVEED is developed by Luiz Antonio Lazarini, an independent developer based in Brazil. For privacy information and requests, contact contato@sveed.com.br.

2. Information used and its purposes

Review activities do not require the child’s name, Brazilian tax ID (CPF), email address, or phone number. The application uses settings, persistent technical identifiers, and local session records, such as date, duration, subject, curriculum skill, correct and incorrect answers, and hint use. This information supports the routine, activity delivery, and local session summaries. It is not a diagnosis or certification of learning. Technical identifiers and records are not described as absolutely anonymous.

3. Storage, connectivity, and backup

Review content and logic run on the Android device. Session records and settings are stored locally; an online account is not required for review. In the documented evaluation configuration, the project manifest does not declare internet permission, and backup is disabled, with exclusion rules for cloud backup and device-to-device transfer. Email support does not give the developer remote access to local records.

4. Text-to-speech and permissions

Prompts are read using the text-to-speech service installed on Android. The text to be read is passed to that service; whether it operates locally or uses a network depends on the engine and voice selected on the device. Please consult the voice provider’s settings and privacy policy. SVEED uses Android features for vibration, reminders, notifications, and the focus-protection overlay during a session. The documented configuration also includes a storage permission limited to Android 9 and earlier for cleaning up legacy SVEED files.

5. Children, advertising, and sharing

Data minimization and child protection guide SVEED’s design. The evaluation version does not include advertising or use review records to sell data or target advertising. Its local architecture does not require these records to be sent to the developer to run review activities. The voice service and website operate as described separately in this policy. Avoid sending identifiable information about children in support requests unless necessary.

6. Retention and deletion

The session-ending flow requests deletion of session records dated earlier than the current date minus 15 days. Cleanup depends on that flow running; it does not guarantee deletion on a particular date while the application is unused. This rule applies to session records and does not set the same retention period for settings and identifiers.

To remove local private data, go to Android Settings → Apps → SVEED → Storage → Clear data, or uninstall the application. Menu names may vary. Deletion removes local history and settings. Any files previously copied or shared outside the application must be deleted separately at their destination.

7. Institutional website and external services

Visiting the website is separate from using review activities in the application. Pages load fonts from Google Fonts; the home pages also load icon resources from jsDelivr. To deliver these resources, the providers receive browser requests containing technical information such as the IP address and request details. Hosting infrastructure may also process technical access logs under its own practices.

The current pages do not include advertising or visitor analytics tools operated by SVEED. Language navigation uses links. See the providers’ information: Google Fonts and jsDelivr.

8. Support and your rights

Parents, guardians, and other data subjects may request information and exercise applicable rights under Brazil’s LGPD, including confirmation of processing, access, correction, and deletion, using the email address above. Support will explain what can be done in each case. Because application records remain on the device, we cannot remotely view, correct, or delete them; we can explain how to manage them locally.

Sending an email provides the sender’s address and message content for handling the request. This information is used to respond and follow up, and retained for the time needed to handle the request and meet applicable obligations. Requests to delete these messages can be sent to the same address. A general question does not require the child’s activity history.

9. Updates

This policy may be updated when the practices described change. The current version’s date appears on this page. New features that change data processing must be accompanied by updated information.
